# 🎯 Une amélioration que je te propose

Je ne créerais **pas** les rôles "Restaurant Owner", "Hotel Owner", "Farmer", etc.

Je garderais seulement **4 types principaux d'utilisateurs** :

* 👑 **Super Admin** : gère toute la plateforme.
* 👤 **Customer** : recherche, commande, réserve, achète.
* 👨‍💼 **Professional** : propose ses compétences (médecin, architecte, développeur, avocat, etc.).
* 🏢 **Business Owner** : crée et gère une ou plusieurs entreprises.

Ensuite, c'est **la catégorie de l'entreprise** qui détermine son métier :

* Restaurant
* Hôtel
* Clinique
* Pharmacie
* Boutique
* Garage
* Université
* ONG
* Coopérative
* etc.

Cette approche rend la base de données plus simple, le code plus maintenable et l'ajout de nouveaux secteurs beaucoup plus facile à l'avenir. Par exemple, si demain tu veux ajouter les salons de coiffure ou les agences de voyage, tu ajoutes simplement une nouvelle catégorie d'entreprise, sans modifier tout le système d'authentification ni créer de nouveaux rôles. C'est une architecture très utilisée dans les plateformes SaaS évolutives.

## 1. L'Amélioration Cruciale : Simplification des Rôles (Refactoring)

Le point le plus important du document est la proposition de **réduire les rôles à 4 types principaux**. Actuellement, notre code (notamment dans `accounts/models.py` ou la gestion des permissions) inclut des rôles spécifiques comme `RESTAURANT_OWNER`, `HOTEL_OWNER`, `MERCHANT`, `FARMER`. 

> [!WARNING]
> **Dette technique imminente**
> Conserver un rôle par métier va rendre le système lourd. Si on ajoute 50 métiers demain, on devra modifier l'authentification et les permissions 50 fois.

**Action requise :**
Il faut basculer vers le modèle proposé :
1. **Super Admin** (Plateforme)
2. **Customer** (Client)
3. **Professional** (Indépendant)
4. **Business Owner** (Propriétaire d'entreprise)

Le métier exact (Restaurant, Hôtel, etc.) sera **uniquement défini par la `BusinessCategory`** (Catégorie d'entreprise) liée au Business, et non par le compte de l'utilisateur.

# 🚀 Nouvelle Organisation Globale du Projet (Isoko Hub)

Voici l'organisation complète et structurée du projet pour matérialiser cette nouvelle idée.

## 🗺️ 1. L'Architecture Globale du Système

Le projet va se diviser en trois dépôts de code (repositories) distincts. Ils communiqueront tous via le serveur central.

```text
                  +-----------------------------------+
                  |        BACKEND (Django + Docker)  |
                  |  Base de données unique Postgres  |
                  +-----------------------------------+
                                    |
            +-----------------------+-----------------------+
            | (Requêtes HTTP / REST API)                    | (Requêtes HTTP / REST API)
            v                                               v
+-----------------------+                       +-----------------------+
|     FRONTEND WEB      |                       |  APPLICATION MOBILE   |
|       (React)         |                       |       (Flutter)       |
+-----------------------+                       +-----------------------+
| - Super Admin (Django)|                       | - Espace Client       |
| - Espace Entreprise   |                       | - Espace Agriculteur  |
| - Espace Professionnel|                       | - Espace Professionnel|
| - Espace Client (Opt) |                       | - Espace Entreprise   |
+-----------------------+                       +-----------------------+
```

---

## 📦 2. Organisation du Backend (Django + Docker)

Le backend gère la sécurité, la base de données et distribue les informations au Web et au Mobile via Django REST Framework (DRF).

- **La Base de Données (PostgreSQL)** : Elle contient une table `User` unique avec des rôles (booléens). Les tables `Product` (biens) et `Service` (prestations) y sont reliées.
- **L'Authentification** : Utilisez des jetons JWT (JSON Web Tokens). Quand le Web ou le Mobile envoie un email/mot de passe, Django valide et renvoie le Token + le rôle de l'utilisateur.
- **La structure Docker** : Un fichier `docker-compose.yml` à la racine du backend qui lance deux conteneurs : l'application Django et la base de données PostgreSQL. Cela rendra votre déploiement sur un serveur (ex: VPS Linux) extrêmement simple plus tard.

---

## 💻 3. Organisation du Frontend Web (React)

Le site web est conçu en priorité pour les écrans d'ordinateurs. C'est l'espace de gestion lourde.

- **Espace Entreprise** : Tableaux de bord, graphiques de ventes, gestion des stocks, listes d'employés, abonnements.
- **Espace Professionnel** : Publication des offres de services, gestion des candidatures complexes, édition de profil, calendrier de rendez-vous.
- **Le cas du Client & de l'Agriculteur** : Sur le web, vous pouvez simplement créer une page vitrine qui explique le concept et affiche des boutons "Télécharger l'application sur le Play Store".
- **Le Super Admin** : Utilisez directement l'interface d'administration native de Django. Elle est sécurisée, incluse d'office, et vous évite de coder un panneau d'administration de zéro en React.

---

## 📱 4. Organisation de l'Application Mobile Unique (Flutter)

Vous publiez une seule application sur le Play Store. Le code Dart de Flutter va gérer l'affichage de manière dynamique après la connexion.

- **Écran d'accueil commun** : Une seule page de connexion/inscription pour tout le monde.
- **Le Système de Routage (Role Guard)** : Une fois connecté, le code Flutter lit le rôle reçu de Django :
  - `role == 'client'` ➡️ Redirection vers l'**Espace Client** (Recherche de produits/services, panier, paiement, suivi de livraison).
  - `role == 'farmer'` ➡️ Redirection vers l'**Espace Agriculteur** (Interface ultra-simplifiée avec un gros bouton "Publier ma récolte" et choix de la province comme Gitega, Ngozi, etc.).
  - `role == 'professional'` ➡️ Redirection vers l'**Espace Pro Mobile** (Messagerie instantanée avec les clients, alertes de nouveaux rendez-vous).
  - `role == 'company'` ➡️ Redirection vers l'**Espace Entreprise Mobile** (Alertes urgentes, validation rapide des commandes, scan de QR codes pour les livraisons).

---

## 📅 5. Plan d'Action pour le Développement (Étape par Étape)

Ne développez pas tout en même temps pour ne pas vous décourager. Suivez cet ordre précis :

1. **Étape 1 (Le Cœur)** : Créez l'environnement Docker avec Django et Postgres. Codez le système d'inscription, de connexion et les profils utilisateurs.
2. **Étape 2 (L'API Catalogue)** : Créez les routes dans Django pour permettre de publier un produit ou un service, et de les lister.
3. **Étape 3 (Le premier Frontend - Priorité Mobile)** : Créez l'application Flutter. Codez l'authentification et l'Espace Client / Agriculteur. Connectez-les à l'API Django. À ce stade, vous avez déjà un produit minimal viable (MVP) qui fonctionne sur téléphone.
4. **Étape 4 (Le second Frontend - Web)** : Créez le site React. Codez l'Espace Entreprise / Professionnel pour leur permettre de gérer leur activité confortablement sur ordinateur.
